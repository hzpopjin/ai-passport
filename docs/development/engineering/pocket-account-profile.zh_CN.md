# Pocket 账户资料

候选版为已绑定卡片增加用户信息页：64×64 头像、用户名、规范公开账号 UID 和站点账户积分。页面展示上次手机同步的快照。游戏心心与星星仍是独立存档字段。完整游戏存档获得持久 ACK 后，资料同步失败只标记待同步，不撤销游戏同步成功状态。

原生首页将 **用户信息** 作为设置之后的独立第七个顶级选项卡。上下键循环切换七个标签，只显示当前选中标签的名称，不在其他标签下方保留用户信息快捷行。按 OK 打开选项卡。设置保留账号入口。长按 OK 返回进入前的首页标签或设置选项。入口及标题不依赖资料快照或后端可用性：已绑定但没有快照的卡片显示 **等待手机同步资料**。未绑定卡片仍保留配对门禁；DEV 仍是离线体验，不开放账号权益。导航来源只存在于内存，不改变存档。

顶栏标题、爱心及百分比统一使用16px字体和共同基线；电量宽度固定为 `100%` 的实测文本宽度，蓝牙断开时保留图标位置。充电图标单独做明确状态的布局验证；当前 BSP 只提供 SOC 和电压，因此不会将100%或 USB 连接猜成充电状态。

## 账号与传输契约

手机复用现有 WordPress 用户中心适配器及已认证缓存：iOS 的 `WPAuthManager.getUserInfo()` / `WPAPIClient.fetchPointsBalance()`，小程序的 `api.getWPUserInfo({persist:false})` / `api.getWPPointsBalance()`，分别使用 `/wp-user-center/v1/user/info` 和 `/wp-user-center/v1/points/balance`。无需部署新的 `GET /api/v1/passport/phone/profile`。现有手机激活、签名权属及完整游戏同步仍是必要能力，本次仅替换公开资料的来源。

规范 UID 为当前认证 WordPress 账号 ID（1 至 UINT32_MAX），不能从二维码或卡片身份推导。响应必须匹配该账号；退出登录、切换账号/会话、凭据被拒绝及账号注销会阻止资料写入。手机将用户名规范为 NFC，去除控制字符、双向文本覆盖符及不完整代理标量，按完整码点截断为最多 63 个 UTF-8 字节；空名使用 `UID <account_id>`。仅复制公开用户名、UID、头像和积分，不向卡片传邮箱、电话或凭据。

优先通过现有用户中心读取刷新资料和积分。网络失败时可保留同一认证账号的公开缓存资料及之前的有效余额；资料缓存以账号和会话隔离，新会话不继承其他账号的积分。缺失/非法积分为 JSON null，不能填零或游戏余额；有效零余额正常保留。既有协议 `points_status: fresh` 表示有数值快照，包括缓存快照，并非实时更新保证。卡片显示 **上次积分**，同时注明资料为上次手机同步快照；不开放离线积分消费。

手机下载公开 HTTPS 头像，不转发 JWT 或 cookies。源文件最多 2 MiB、每边最多 4096 像素、总像素最多 4,000,000，支持静态 PNG/JPEG/WebP。两端居中按比例填充裁切，透明区域合成到白底，缩为 64×64，再编码为小端 RGB565。卡片仅接收恰好 8192 个原始字节，不请求 URL、不解码图片。缺少头像使用相同占位图，SHA256 为 `aa86924dfd5550307ff3e8840c21df0248b2af0784f2580b262210877e6f0c3b`。不同平台的原生缩放可能产生不同像素，不承诺两平台缩放逐位相同。哈希比较对象始终是规范像素字节，不是 URL。

加密且认证的 BLE 手机 RPC 保持外层协议 `pocket-phone-jwt-v1`，包含 32 位小写十六进制 `request_id`、当前 `expected_epoch`、`action` 和一个 `profile` 对象。账号 JWT、头像 URL、邮箱、电话号码均不发送到卡片。所有资料动作拒绝未绑定或锁定、待解绑、错误账号与错误 epoch。

| 动作 | profile 的精确字段 |
| --- | --- |
| `profile_begin` | `account_id`、`sha256`、`format`、`width`、`height`、`bytes`、`username`、`uid`、`points_status`、`points` |
| `profile_chunk` | `account_id`、`sha256`、`offset`、`data` |
| `profile_commit` | `account_id`、`sha256` |

`format` 为 `rgb565-le`，尺寸 64×64，`bytes` 为 8192。每块 512 字节编码为 1024 个小写十六进制字符，偏移从 0 到 7680 且按 512 对齐。既有 4096 字节 RPC 上限不变。状态可选返回 `profile`，包含 `enabled`、固定格式/尺寸、已提交 `sha256`/`revision`、待提交 `upload_sha256`/`next_offset` 与已提交公开元数据。旧卡没有该能力或能力禁用时跳过。完整元数据和哈希相同不写入；头像哈希相同但元数据变化时在 Flash 内复制已验证像素，不经 BLE 发像素块。手机在提交后核验最终哈希和元数据。

## Flash 持久存储与归属

仓库默认分区表仍保持原来的最小布局。在该布局下资料与持久日志禁用，不发生数据分区 I/O。组合候选由 `partitions-pocket-profile-candidate.csv` 和 `sdkconfig.pocket-profile-candidate` 定义，在隔离构建中排在 `sdkconfig.defaults` 后使用。

| 分区 | 偏移 | 大小 |
| --- | ---: | ---: |
| `nvs` | `0x9000` | `0x6000` |
| `phy_init` | `0xf000` | `0x1000` |
| `factory` | `0x10000` | `0x7c8000` |
| `pocket_profile`（data/0x41） | `0x7d8000` | `0x8000` |
| `pocket_logs`（data/0x40） | `0x7e0000` | `0x20000` |

适配器先核验五个分区的精确身份、范围和标志，再进行资料 I/O。资料区分成两个 16 KiB bank；各有 256 字节版本/CRC 头、+0x100 处像素、+0x3000 处十六个带 CRC 的进度标记及 +0x3fc0 处 CRC 提交尾。只擦非当前 bank；每块写入后读回成功才确认进度标记。恢复时校验已持久前缀，完整像素通过 SHA256 后才用提交尾切换版本。启动选择完整有效的已提交 bank；中断写入保留旧头像，丢失最终 ACK 可以恢复。存储不确定时先重读，再选择可擦 bank。所有读写限于 32 KiB 资料分区，流式 SHA 使用 512 字节缓冲。

元数据同时绑定账号与归属 epoch。解绑立即从当前 UI/RPC 隐藏旧资料、待传状态和头像。bank 里可能保留旧字节；这是逻辑账号隔离，不是安全擦除。资料存储不改游戏/V4 存档、NVS 布局、蓝牙 bond 或安全状态。使用既有 8192 字节手机 worker，不增加资料任务。UI 保留一份 8192 字节像素视图和少量元数据；已提交版本变化时清理 LVGL 图片缓存。LVGL 操作仍在 BSP 锁内。独立 PIN 页优先并隐藏用户资料和管理控件。

## 验证与待验收项

主机测试覆盖擦除、头、每块及进度标记、提交的字节前缀失败，以及重启续传、丢 ACK、账号/epoch 隔离、UTF-8、空积分和相同哈希。实际 C 手机 RPC 与 Swift、小程序互通。ESP 适配器测试验证缺少/错误布局时零 I/O。实际 C/LVGL 渲染验证头像替换、最大 UID/积分、积分不可用、归属隔离及独立 PIN 优先，主机 LVGL 池为 48 KiB。Xcode 模拟器测试构建真实 App。这些不等于实体卡或真实账号端到端验收。

所有静态 UI 文本由重新生成的 492 字形子集覆盖。任意 Unicode 用户名可正确存储，但不在固件字体中的字符会显示占位字形；当前公开拉丁字母用户名已覆盖。头像解码、蓝牙共存、Flash 停顿、最低堆/栈余量和断电仍需明确授权后的实机验收。小程序源码测试不替代微信基础库、权限、域名白名单与设备解码验证。

本次资料来源无需新后端接口；源码准备本身不刷入分区迁移。回收原 factory 尾部 `0x7d8000..0x7fffff` 需要按最终产物和数据影响范围另行批准；该尾部未读回、未证明为空。使用最终配套 app/分区表操作单，不使用带填充合并镜像、替换 bootloader、整片擦除或完整 `flash_args`。回退使用保留的上一版 app 和最小分区表，保留 NVS/PHY/bond；资料与日志字节可留在 Flash 上但失去作用。单 factory 更新中断可能需要 USB 恢复。
